# CLAUDE.md

Email drafting + daily summary on a Hetzner host (`hezner.morganrivers.com`,
`/opt/letterlock`, systemd), plus a five-role enclave build for Phala.

## Deployment

Server has no git repo. Never `scp` single files or edit remote files in place.

```bash
./deploy/deploy.sh              # rsync + daemon-reload + restart
DRY_RUN=1 ./deploy/deploy.sh
SERVICES="email-daemon.service" ./deploy/deploy.sh
```

`--delete-after` is authoritative, so `EXCLUDES` must track the server-only files
below. Units restarted are each `.service` with `[Install]`; every `.service`
gets the sandbox drop-in whatever starts it. There are no timers: the schedule
is `backend/daemons/scheduler.py`, a thread in the mail daemon, and the three
`.service` units it replaced remain only as the sandboxed way to run one job by
hand. `RETIRED_UNITS` in `deploy.sh` disables the timers it used to install.
`deploy/preflight.py` runs first and leaves a failing unit alone rather than
restarting it into a crash loop.

Nothing runs as root. `hardening.conf` installs as a per-unit `10-hardening.conf`
drop-in; exceptions go in `deploy/hetzner/<unit>.d/*.conf` numbered above it. Five
units have their own account (`cosigner`, `egress-proxy`, `letterlock-web`,
`letterlock-hook`, `letterlock-billing`), derived along with group membership from
`User=`/`SupplementaryGroups=` there. Groups: `letterlock-data` (`database/`,
`state/`), `letterlock-secrets` (`.env`), `letterlock-wake` (FIFO + wake spool),
`letterlock-billing-queue`. Known residual: the web tier can read
`POLAR_API_TOKEN`, which shares `.env` with `SESSION_SECRET`. Separation of
privilege on one box, not of operator; no product copy may say otherwise.

Caddy config is generated, not synced: `python -m deploy.render_caddyfile >
deploy/hetzner/Caddyfile`, then scp, `caddy validate`, install, reload.

## Dependencies

`requirements.txt` is the only shipped list; `deploy/phala/pyproject.toml` is
generated from it (`python -m deploy.render_pyproject`, then `cd deploy/phala &&
uv lock`) and `tests/test_requirements.py` fails on drift. flake8, isort and
bandit run from `tests/test_lint.py`; bandit runs twice, `SHIPPED` skipping only
`B101` and `OPERATOR` (`deploy/`, `tools/`) also `B404`/`B603`/`B607`, anything
else a per-line `# nosec <id>  # reason`. `python -m deploy.audit` audits
`uv.lock` under `LETTERLOCK_AUDIT=1`, expiring entries in
`deploy/audit_ignores.toml`. Dependabot is security-only against
`requirements.txt`; never point it at `uv`. The Presidio PII analyzer is off by
default (~1.6 GB).

## Enclave split

Five roles, one container and image each: `mail`, `web`, `hook`, `egress`,
`ingress`. Names live in `backend/roles.py` alone; `DATA_ROLES` and
`NETWORK_ROLES` partition them and a role in both is refused. The `inner` network
is `internal: true`, so containers on it reach the internet only through `egress`.
`ingress` holds every published port, so `web` and `hook` have no `ports:`.

The compose file is the secret partition and its hash is measured into RTMR3.
Never bind-mount `/dstack/.host-shared`; every interpolated name must be in
`allowed_envs` in `app-compose.json`; `EXPECTED_COMPOSE_HASH` must be set. The
entrypoint runs `python -m backend.tee.tee_boot "$role"`, which refuses an unknown
role and checks `REQUIRED_BY_ROLE` plus `CAPABILITIES_BY_ROLE`. `hook` gets no
`database/` and no guest-agent socket; `web` needs the socket, so its isolation is
`token.bin` at 0600 to the mail uid. Membership is `group_add:`, never numeric
`user:`. No role is a Polar receiver: entitlement is `confirm_checkout()` plus the
3-hourly poller, both in `mail`. `web` holds no inference key.
`tests/test_enclave_boundary.py` pins all of it.

Image contents are per role in `deploy/phala/image_files.nix`, generated by
`python -m deploy.render_image_manifest [--check]` from `tools/reachability.py`
walking each role's entry points. Function-local imports count like top-level
ones, so cutting a role's reach means moving code, never deferring an import.
`tests/test_image_manifest.py` fails on drift and refuses `deploy/`, `tests/`,
`tools/` or `docs/` files and any shipped `subprocess`/`eval`.

## Server-only files (each has a matching `--exclude`)

- `.env` — inference keys, `SESSION_SECRET`, `POLAR_API_TOKEN`; must not exist
  inside the enclave. `.env.billing` — `POLAR_WEBHOOK_SECRET` only. `.env.alerts` —
  Telegram token and chat id, read by systemd for the co-signer alone, by hand.
- `.gmail-mcp/gcp-oauth.keys.json` — OAuth app keys, refused under `TEE_REQUIRED`.
- `state/` — daemon scratch, FIFO, both spools and their locks. Spools name people
  and clear on the next drain; anything longer-lived belongs in `audit.py`.
- `database/` — `accounts.json` is the manifest and the only plaintext; every
  `<id>/` file is ciphertext costing a rate-limited co-signer round trip.
  `accounts.lock` guards every manifest write via `_manifest_transaction()`.
- `config/` — operator prompts from `~/.system_files`. `venv/`.

## Runtime paths

- `daemon_loop.py` — FIFO listener, `email-daemon`. Routes to `manual_draft` or
  `draft_replies`, runs `handoff_server.start()` and `scheduler.start()` on
  threads, drains billing.
- `gmail_hook_server.py` — Pub/Sub webhook (8787): verify OIDC JWT, spool the
  address, poke the FIFO. Never resolves addresses; an unparseable body wakes
  nothing (an address-less wake swept every account into `_sweep_refusal`).
- `backend/spool.py` — the one append-and-drain protocol behind `wake_queue.py` and
  `billing_queue.py`. Billing acks on spool, retries with an attempt count, alerts
  on drop; the 3-hourly poller re-derives subscription status.
- `daemons/scheduler.py` — `SCHEDULE` is the only statement of when the three
  clock-driven jobs run: `email_summary.py` (05:00 UTC), `watch_renew.py`
  (Mon 04:00 UTC, `users.watch`), `billing_poller.py` (every 3h). A thread in
  the mail daemon in both deployments, replacing three systemd timers and a
  crontab. `state/schedule.json` records the last run; a missed time runs at
  the next tick, a missing marker seeds and does not.
- `frontend/web_server.py` — product UI (8790), own uid. Anything needing a Google
  token or a Polar call goes to the daemon over `custody/handoff.py`. `/contact` is
  the one unauthenticated relay: per-IP bucket, length cap refused not truncated.
- `cosigner/server.py` — co-signer (8791, client certificate required). Holds the
  outer wrapping key and DPoP key and no ciphertext. Hard dependency, no bypass.
- `daemons/egress_proxy.py` — CONNECT proxy (8792), the only process with network
  access; every other unit runs `IPAddressDeny=any`. No direct-connection fallback.
- `daemons/ingress_proxy.py` — enclave-only inbound forwarder; `daemons/relay.py`
  is the byte pump both proxies share.

Changes take effect on restart; the daemon also honors `restart.flag`.

## Asserts and refusals

An `assert` states an invariant that is a programmer error if false. Anything
validating a value that crossed a trust boundary (Google, co-signer, KMS, web
form, model, file) is an explicit `raise` of a named type: `InvalidAccountData`,
`MaskingFailed`, `AllowlistInvalid`, `DataKeyExists`, `CustodyError`,
`AttestationRefused`, `HookError`. Never catch one into a fallback. No control may
be spelled as an assert, since `require_asserts()` covers only boots through
`backend/__init__.py` and `cosigner/__init__.py`: running under `-O` must cost
invariant checking and no control, which `tests/test_optimized_controls.py` proves.

## Single sources of truth

Import from these; never copy the behavior.

- `secrets.py` — the only read of `.env`. `secrets_checks.py` — the
  `*_configured()` checks, `REQUIRED` and `REQUIRED_BY_ROLE`.
- `frontend/session.py` — the signed cookies and keyring; `kid:value:iat:mac` is
  what makes `SESSION_SECRET` rotatable via `SESSION_SECRET_PREVIOUS`.
- `backend/site.py` — hostnames, ports, URLs, and `TRUSTED_PROXIES`, the only peer
  whose `X-Forwarded-For` is read.
- `backend/egress.py` — every reachable hostname, derived at render time into
  `egress_allowlist.json`. Exact matches, names not addresses, fail closed.
- `backend/http_client.py` — the only outbound HTTP: https only, certifi, required
  `timeout`, no redirects without a budget with each hop re-checked.
- `cosigner/` — imports nothing from `backend/` but alerts. `keys.py` owns outer-key
  derivation, DPoP signing and rotation; `policy.py` decides every request and
  writes its own audit row; `retention.py` is the only deleter; `attest.py` holds
  the measurement allowlist. Accounts are named by opaque handle, never an id.
- `custody/` — one 32-byte data key per account: `keyring.py` mints and caches,
  `wrapping.py` is the inner AES-GCM layer, `client.py` the only co-signer network
  boundary, `tokens.py` the only path to an access token, `rotate.py` rekeys without
  opening a record. Ours inside, theirs outside; `dek_for()` stays cached under
  `policy.DISTINCT_WINDOW_SECONDS`; nothing takes a bare account id.
- `custody/handoff.py` — the wire contract for work the web tier may not do (Google
  tokens, `chat-*`, `providers`, `checkout-*`, `account-forget`). Unix socket at
  0660 plus `SO_PEERCRED`. `HandoffUnavailable` renders 503, never a local fallback.
- `onboarding/provisioning.py` — the Google consent sequence; `missing_scopes()`
  runs off the redirect and again off the token response.
- `backend/paths.py` — locations and their modes. `data_gid()` of None falls back to
  owner-only; `write_private` creates at 0600 rather than narrowing later.
- `integrations/gmail_gcal/` — the only Google code; credentials carry no refresh
  token. Writes go to `WRITE_CALENDAR`, no attendees, capped fields, and only after
  `write_calendar_audience()` confirms nobody but the owner can read it. Search puts
  one header value in a query, after `ADDRESS_QUERY_RE`.
- `llm_client.py` — provider catalog and masking boundary. `make_client()` and
  `resolve()` are the only constructor and chooser, and a stated preference raises
  rather than substitutes. `confidential=True` waits on `inference_attestation`.
  Always `/v1/chat/completions`. `ProviderUnavailable` alerts and never falls back.
- `tee/quote_policy.py` — the five checks authorizing a TDX quote, used inbound by
  `cosigner/attest.py` and outbound by `inference_attestation.py`, which binds
  report_data to signing address, nonce and requested model.
  `inference_allowlist.json` is the reviewed pin list; RTMR3 does not measure the
  model server, so `ComposeLog` pins each compose by `file_sha256`.
- `backend/audit.py` — the web tier's SQLite record of what a person changed,
  written by the account mutators rather than the routes; `detail` takes only short
  tokens, and it shares no code with the co-signer's log.
- `accounts/chat_link.py` — who may change a telegram target. A linked chat must
  post a code from that chat to unlink; with none linked the mailbox is asked
  (insert, never send). Changing a target is unlink then link. `set_telegram()` is
  the sole writer; `USER_MESSAGES` is every refusal the web tier may render.
- `draft_replies.drafting_instructions()` — the one assembly of voice profile plus
  personal context. `voice_dna.py` says which profile applies; generation is
  `voice_generation.py`, since it reads mail and runs inference. Profiles land in
  `database/<id>/voice-dna.enc`, never `config/`.
- `agentic_drafter.Fence` — the fence around outside content; `new_fence()`,
  `wrap()` and `rule` travel together, delimiters carry a per-conversation nonce
  and `wrap()` strips it from the content.
- `masking/pseudonymizer.py` — Presidio NER or regex, chosen by `new_state()`; both
  run the deterministic layers and tag through `_tag_value()`. `protect()` names
  text masking must leave byte-identical, as a token rather than a shape.
- `PolarBilling.resolve_account()` — resolves one direction only, which makes it an
  ownership test on a browser-supplied id. `checkout_url()` stamps
  `CHECKOUT_ACCOUNT_KEY`, `customer_email` is only a fallback,
  `_static_checkout_url()` is refused under `TEE_REQUIRED`,
  `set_polar_customer_id()` refuses a customer another account holds, and
  `polar_api.valid_id`/`_segment()` are the floor under every caller.
  `billing.PLAN_PRICE_EUR` is the quoted price.
- `draft_replies` — `build_draft_payload()`, `submit_draft(..., draft_id=None)`
  (sole boundary to `gmail_gcal.drafts`), `gmail_thread_link()`,
  `format_draft_line()`. `tools/render_brand.py` rewrites `frontend/static/`; new
  assets go in `web_server.STATIC_TYPES` too.
